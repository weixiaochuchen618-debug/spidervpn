## 权威来源与恢复顺序

1. 遵守用户最新明确目标、项目全局开发协议及现有安全约束。本目录不授予任何新增权限，不取代正式任务锁。
2. 优先读取 [TASK_ASSIGNMENTS](../security/TASK_ASSIGNMENTS.md) 最新有效章节、[AGENT_COLLABORATION](../security/AGENT_COLLABORATION.md)、[AGENT_HANDOFF](../security/AGENT_HANDOFF.md) 最新交接、本角色最新正式授权及相关 Issue/PR。若总控已建立当前状态索引，可先读取索引，但仍以正式授权及原始证据为准。
3. 核对实际 main、当前累计候选（如适用）、本角色分支/HEAD、关联 PR、Issue、CI、任务锁、最近交接和待办。文档与实时状态不一致时先核实，不将最新提交自动视为授权或验收。
4. [REMEDIATION_BACKLOG](../security/REMEDIATION_BACKLOG.md) 为缺陷账本，[SECURITY_REMEDIATION_PLAN](../security/SECURITY_REMEDIATION_PLAN.md) 为技术方案及验收依据；按任务需要追溯历史，不默认全量读取、复审或复制历史材料。
5. 新窗口为同一 Agent 的接续而非新增 Agent。确认旧窗口已停止相关写入、最新任务锁允许本窗口执行；用户确认与 GitHub 状态核对不等于能技术证明另一个聊天已停止。旧窗口锁尚未转移、存在异常 HEAD 移动或权限冲突时停止写入、保持只读，报总控处理。总控也须确认旧总控停写后方可恢复全局写权。未授权不得创建重复分支或 PR。
6. 每轮以最新有效任务继续，不重新初始化、不绑定固定阶段、Issue、PR、SHA 或历史分支。角色名称不等于开发权限；实际范围以最新有效正式分配为准。

## 产品交付优先

当前项目定位为个人自用、持续开发的 VPN 产品，具体目标以用户最新明确要求为准。优先推动真实可编译、可启动、可导入配置、可连接/断开/重连、系统代理恢复、服务端授权/撤销与部署回滚，以及必要的 WFP 防泄漏等功能闭环；正式发行工作随实际需求安排。不能绕过相应功能所需的安全前置条件。

每项任务明确产品目标、最小必要范围、验收标准、停止条件及集成路径。以实际功能、可验证构建、有效回归和真实验收衡量进度，而非文档、Issue、PR、审计、测试或提交数量。优先继承与集成已有成果，避免孤立候选和无明确集成路径的堆叠式 PR。

仅在以下情形开启新的专项或扩大审查：真实产品失败；有具体调用路径、触发条件和影响的生产可达缺陷；新变更使既有证据失效；当前目标必须满足的验收/安全门槛。明确的静态证明也可成立，不要求先发生真实事故。其他改进记录为后续优化，不自动阻塞当前限定交付。重大安全问题如实报告，不以产品优先为由掩盖。

不默认重复已验收的相同 SHA/范围/证据，不因理论风险自动重启冻结任务，不无限增加测试排列、检查器补强或通用验证框架。达到约定的限定验收与停止条件即收敛；无有效任务则空闲，不为保持窗口活跃而制造工作。


### 长期产品传输验收规则（用户 2026-11-28 确认）

**标准 UDP 和兼容 TCP 各在支持该传输的环境完成一次真实端到端验收即可。** 两次可以使用不同的服务器或线路。单条线路有一种经验证的传输即可满足日常连接。验收记录实际提交和环境，以及认证、真实隧道出网、断开、适用的重连和代理恢复结果。

部分服务器环境无法建立有效的 UDP 隧道，可使用兼容 TCP。产品负责人确认 `mvp04-debug` 的 UDP 出网失败源于该线路的服务器限制，按环境限制结案，作为非阻塞线路记录。[验收账本](../security/REMEDIATION_BACKLOG.md#d157-2026-11-28-传输验收标准与受限线路结案) · [Issue #94](https://github.com/weixiaochuchen618-debug/spidervpn/issues/94#issuecomment-7212384390)

各有一次有效验收后即收敛。已确认的线路限制停止复测、排障、修补和追加审计。后续仅在用户明确提出新需求、相关变更使既有证据失效，或受支持环境出现真实产品回归时，按实际范围验证。WFP 持久 BLOCK 和真实防泄漏按各自的安全验收要求取证。

## 电脑 1 开发工作流

电脑 1 是默认开发环境。代码修改、调试、Windows 构建、隔离功能验证和日常集成都在本机完成。现有 GitHub Actions 继续提供 Windows MSVC 和 Linux 等原生验证。ELEVEN 保留为按需实机复验设备。

Codex 负责规划、验收和交接。文件范围明确的实现任务可交给本机 CodeBuddy CLI，使用 `deepseek-v4.1-flash --effort max`。Codex 复核实际差异和必要验证。调用超时或受阻时，总控直接在本机工作区接续。GitHub 用于代码、CI 和验收记录。

本机日常开发使用独立工作树和隔离数据目录。涉及真实网络、系统代理、路由、WFP 或现役 VPS 的实机操作，以对应任务的授权和环境为准。同一候选已有的实机证据按记录的范围采用。

## 不可违反的约束

- 新增及修复逻辑遵守 Rust 编译要求；PowerShell 仅薄包装。保持现有 UI、连接交互、用户操作习惯和 WFP 持久 BLOCK；不擅自改变实验功能默认状态。
- 不越权修改路径、其他 Agent 分支、共享接口或 CI；禁止直接提交 main、强推、重写共享历史。非预期 HEAD 移动立即停写，报总控。
- 不删除、禁用、跳过失败测试，不降低安全断言；保留已有环境限制和历史失败证据，不新增排除来获取绿灯。
- 按当前任务实际执行适用的 MSVC/GNU/Linux Rust 构建、专项正反回归及 CI；准确关联 commit SHA、Run ID、必要原始日志和未执行项。不把旧 SHA、模拟或 CI 通过冒充真实安全验收。
- 不未经授权修改真实 Windows、VPS、WFP/BFE、路由、注册表，启用实验功能、安装/运行未经批准的第三方依赖或执行生产部署；隔离实验不冒充产品实机测试。
- 区分代码候选、开发构建、隔离验证、真实产品验收、完整安全验收与正式发行。未完成真实安全验收不得宣称已修复或合并 main；合并需总控核对完整 DoD、依赖、最新 HEAD/CI 及用户明确授权，不启用 auto-merge。
- 缺实际环境时据实记录 BLOCKED/NOT RUN 及最小所需条件，继续不受影响的授权工作，不以无穷模拟替代实机验收。
- Agent 编号是逻辑身份，共享 GitHub 凭据不代表独立账号审批或技术强制隔离。
